OBS Studio, finally usable by ear.

OBSSpeaks patches OBS Studio itself — the free, open-source software behind most of the world's livestreams and broadcasts — so a blind creator can run it entirely by ear. It's Visionary Software's third proof of the same method that built AccessBridge, and it's entering its first tester cohort now.

01The gap

OBS was never built to be heard.

That isn't an impression — it's the documented state of the software today.

  • It isn't listed in AppleVis.AppleVis is the directory blind Mac users search first for accessible software. OBS Studio — one of the most-used pieces of software on the internet — isn't on it.
  • Its own community says to switch to Windows.Blind Mac users asking for help on OBS's own forums are routinely told there's no good answer on the Mac — go use Windows instead.
  • The maintainers have said plainly nobody is positioned to fix it.OBS's own accessibility discussion thread (GitHub Discussion #6192) states outright that the project has no VPAT or accessibility report, and no one on the team has the skills to pursue one. The only macOS-targeted accessibility change ever merged upstream, in the project's whole history, is a single one-line combo-box fix.
  • The bugs are filed, and stay open for years.Issue #3524 documented a full accessibility regression; issue #3627 catalogued blind users unable to start a stream or recording at all; issue #11400, opened in October 2024, is still open today — screen readers can't even read the name of a filter in its own list.
  • A community guide for blind OBS users gives up outright.On positioning a source on the canvas — one of the most basic things a streamer does — it says: "There is no good way around it."
  • Muting didn't even mute.OBS uses a checkable button for its mute controls; a screen reader activates it by toggling, which changes the button's appearance without ever firing the click. The audio kept playing. Open upstream since 2022.
02What OBSSpeaks changes

Fixed at the source, not bolted on.

macOS doesn't let one application add accessibility labels to another — a companion tool can read OBS and drive it, but it can never make OBS itself readable. The only route is changing OBS at the source and rebuilding it. That's what OBSSpeaks is: a clean, rebasable patch series on top of stock OBS, not a fork.

35
Patches rebased clean onto stock OBS 32 — roughly 11,800 lines changed at the source.
7
Console tabs — Scenes, Sources, Audio, Output, Transitions, Support, Manage — full keyboard coverage.
15
Narrated masterclass chapters, recorded before the first outside tester ever opens the app.

i. Every dialog, named

OBS builds its settings UI for every plugin and source type from one shared file — fixed once, at the root, and the fix reaches all of it: source, filter, encoder, and output dialogs across roughly 95 plugin files.

ii. What sight gave for free, spoken

Exact canvas position and overlaps, a frame's brightness and color-key spill, WCAG-style contrast against whatever a source sits on, even whether a camera has a face in frame — read on request, not guessed.

iii. Stays fixed on every OBS release

One command checks for a new OBS version, replays every patch onto it, rebuilds, and verifies — it refuses to install if a patch stopped applying or the accessibility marker is missing, rather than ship a silently degraded build.

Fixed, with the receipts

  • Docked panels restored — Scenes, Sources, Audio Mixer, Transitions — named and bounded again.
  • Keyboard-reachable context menus — scale, blend, deinterlace, group, projector, screenshot — all mouse-only before.
  • Spoken as they update — the core stream-health readout that had zero screen-reader path before.
  • Add Source, fully in-console: type list, nested scenes, reusing an existing source, no trip to the main window.
  • Reset, fit, stretch, flip, center, rotate — plus exact position and overlap on request.
  • A frame's brightness, black/blown-out detection, and color-key spill, read on request.

03Where it stands

Feature-complete. Testers next.

OBSSpeaks hasn't shipped to outside testers yet. What it has already done is skip the part every new product struggles with: it runs the exact tester operations AccessBridge proved in production, built before the first outside tester ever opens it.

Already built, ahead of the first tester

Not a demo waiting for infrastructure — the infrastructure is proven already.

The same playbook AccessBridge already runs: an in-app health beacon, an automatic updater that verifies before it installs, a one-keystroke feedback channel straight to the founder, and a full narrated masterclass — all built and working before a single outside tester has the app.

Still open, and said plainly rather than hidden: an accessible peer for the level meter and preview canvas contents (the frame itself, not its metadata), and full end-to-end verification by ear across every remaining corner — this project has learned the hard way that building correctly and sounding correct by VoiceOver are not automatically the same thing, so nothing here is called done until it's heard.
